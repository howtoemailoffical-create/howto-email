# Security policy

## Reporting a vulnerability

Please do not open a public issue containing exploit details, credentials, private data, or information that would make an unresolved vulnerability easier to abuse.

Use GitHub's private vulnerability reporting feature for this repository when it is available. If private reporting is not available, do not publish sensitive details in a public issue; wait for a private reporting channel to be provided.

## Scope

Security reports should concern the howto.email site, its source code, or its deployed tools. Vulnerabilities in third-party services should be reported to the relevant upstream project or provider.

Public DNS records and ordinary email-configuration findings are not, by themselves, vulnerabilities in howto.email.

## Safe testing

Do not perform destructive testing, denial-of-service testing, credential attacks, or testing against systems you do not own or have authorization to assess.
